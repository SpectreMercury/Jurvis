# 记忆与单窗口：架构设计

状态：第 1、2、3 期已实现（见第 16、17、18 节），并用真实模型跑过一遍（见第 19 节），其余各期是设计稿。本文描述目标架构和从现有代码迁移的分期。

## 1. 要解决的问题

Jurvis 是个人助理，应当被当作一个人来对待。现在的实现里，会话是一切的容器：

- 每个会话有自己的上下文窗口和一份摘要，换一个会话就想不起原话（`memory.excerpts` 只查当前会话）。
- 跨会话只共享一张扁平的 `memories` 表，没有"什么时候、哪次聊到的"，相似就覆盖。
- 助手自己也在开新会话（陪伴模式），目标和定时任务绑在某个会话上。
- 一次回复倾向于把任务做完，很少停下来让用户做选择。

结果是每个窗口里都是一个失忆的分身，共用一本便签。

## 2. 原则

1. **一条流。** 只有一条连续的对话，上下文每一轮现场组装，不重放某个会话。
2. **记忆分层，分处存放。** 知识放文档，经历放数据库，时间和人交给外部工具。
3. **工具是记忆的一部分。** 日历、提醒、通讯录是事实来源，Jurvis 读写它们，不另造一套。
4. **像人一样协作。** 一轮推进一步，先给东西再提问，该用户定的事让用户选。
5. **越用越会做事。** 从结果和用户的选择里改进做法，但不能改自己的权限。
6. **用户看得见、改得了。** 它对用户的认识是可读可改的文档，每次自我改动都能撤回。

## 3. 总览

```
┌──────────────── 对话流（唯一窗口） ────────────────┐
│  消息 · 卡片 · 提问选项          「等你决定」区域     │
└───────┬───────────────┬───────────────┬───────────┘
        │               │               │
   每轮组装上下文     任务与提问        空间（卡片打开）
        │               │               │
┌───────▼──────┐ ┌──────▼───────┐ ┌─────▼─────────┐
│ 文档库        │ │ 数据库        │ │ 外部工具       │
│ 知识          │ │ 经历与索引     │ │ 时间与人       │
│ Markdown     │ │ SQLite       │ │ 系统为准，双向  │
└──────────────┘ └──────────────┘ └───────────────┘
        ▲               ▲
        └── 夜间巩固 · 反思 · 学习（后台） ──┘
```

## 4. 对话流

### 4.1 一条主流

- `sessions` 表保留，增加 `kind`：`main` 只有一条，是用户看到的流；`work` 是后台工作上下文（后台任务、定时运行、学习、代码长任务），不作为窗口展示，结果以卡片投递进主流（沿用 `store.deliver`）。
- 原来靠开新会话解决的事，变成主流里的状态：

| 原来 | 现在 |
|---|---|
| 换话题开新会话 | 自动切出新的一段经历（见 5.2） |
| 陪伴模式的独立会话 | 主流里的一种状态，进入和退出都在流里 |
| 代码会话 | 挂在当前这段上的工作台，聊到该项目时加载其上下文 |
| 无痕会话 | 流里一段标记为"不记"的区间，不编码、不抽取 |
| 每会话的模型、命令许可 | 改为全局偏好加按任务的许可 |

### 4.2 回复的形态

- **多气泡**：一次回复可以拆成几条短消息：应答、事实、重点、提问各占一条。
- **先说要做什么**：动手前用一句话说明要查什么、做什么。
- **节奏按事情的性质定**：

| 事情 | 节奏 |
|---|---|
| 简单问答 | 直接答，不带选项 |
| 开放式的探讨和规划 | 一步一停：先给当前的东西，再用选项问下一步 |
| 目标明确的执行 | 开头确认关键的不确定点，然后做完，遇到真岔路才停 |

### 4.3 任务与提问

任务是流里的持续对象，跨多轮、可跨天。

- 状态包括：目标、已定的决定、进度、待回答的问题、关联的空间。
- **何时提问**：三件事同时成立才问：确实不确定、做错的代价不小、从记忆里推断不出来。
- **怎么问**：一次一件；2 到 4 个选项，用用户的口吻写；带它自己的建议；保留一个"先不做"的出口。不依赖答案的部分先做着。
- **岔开与回到主线**：用户中途问别的，简短回答后回到任务，任务状态不丢。
- **「等你决定」区域**：所有未回答的问题常驻在流之外的一个区域，不随消息滚走。这是对话流之外唯一常驻的界面元素。
- **搁置不丢**：用户选"先不做"的事转为它持续关注的目标。
- **选择即信号**：同类问题用户几次选了同样的答案，之后不再问，按习惯做并说明（见第 9 节）。

## 5. 记忆

### 5.1 六层

| 层 | 内容 | 存放处 | 何时进上下文 |
|---|---|---|---|
| 工作记忆 | 当前这段的原文、未完的任务 | 数据库 | 每轮 |
| 核心画像 | 用户是谁、重要的人、近况，约 500 字 | 文档库 `我.md` | 每轮 |
| 做事规则 | 习惯、技能、例行 | 文档库 | 按任务类型加载 |
| 情景记忆 | 一段段经历及其日、周、月概要 | 数据库 | 被唤起时 |
| 语义记忆 | 关于用户的事实，带出处和新旧关系 | 文档库 | 被唤起时 |
| 前瞻记忆 | 将要发生的事、答应过的事 | 外部工具、定时任务 | 今天和临近的每轮，其余被唤起时 |

### 5.2 一段经历

主流被切成一段段经历（episode），取代现在每个会话一份的滚动摘要。

- **切分**：停顿超过约 30 分钟一定切；连续对话中话题明显转向也切，由本地模型判断。
- **内容**：起止时间、标题、摘要、话题、涉及的人、显著度、敏感标记、向量。原文永久保留在 `messages`。
- **补救**：夜间巩固可以合并或拆分切错的段。
- **同一天聊回旧话题**：不合并，两段互相链接。

### 5.3 四个过程

1. **编码**：一段结束后，写摘要、抽取事实、留经验记录。现有的 `Memory.extract` 改为按段执行。
2. **巩固**：每晚空闲时运行。把当天的段写成一页日记；更新涉及的人物页和主题页；重写核心画像；向上合成周、月概要。新旧事实矛盾时标注"之前是……"，不抹掉旧的。
3. **回忆**：打分为相关度 × 重要度 × 新近度。支持时间线索（"上周"）和人物线索。先命中摘要和文档页，顺着链接多带一层，需要原话时再取原文。现有的向量检索和字面匹配两条路都保留。
4. **遗忘**：强度随时间衰减，被用到则加强（沿用 `used_at`）。遗忘是不再主动浮现，文件和原文不删。

### 5.4 每轮的上下文

顺序固定，稳定的在前，以便模型服务复用缓存：

```
系统提示
核心画像
本次适用的习惯和技能说明
── 以下每轮变化 ──
今日概要、今天和临近的日程、未完的任务和待答的问题
被唤起的经历摘要、文档页、原话摘录
当前这段的原文
用户的新消息
```

## 6. 文档库

知识层的事实来源，是一个 Markdown 文件夹，可用 Obsidian 打开。不依赖 Obsidian。

- **位置**：`data/vault/`，和其余数据一样仅本人可读，默认不同步。
- **归属**：整个库归 Jurvis 所有。用户打开是为了查看和纠正。

```
vault/
├── 我.md              核心画像
├── 人物/              每人一页，对应通讯录
├── 主题/              每个主题一页；长期目标的空间也在这里
├── 习惯/              用户希望它怎么做事
├── 技能/              某类任务的做法（SKILL.md 格式）
├── 例行/              什么时候主动做什么
└── 日记/              每日概要，如 2026-11-21.md
```

- **页面格式**：开头是属性区（重要度、敏感、更新时间、类型），正文是事实条目，结尾列出处。出处链接到日记页，日记页能定位到原始对话。
- **链接**：`[[页面名]]`。检索时顺着链接多带一层；也是 Obsidian 关系图的来源。
- **编辑规则**：用户改过的内容以用户为准，巩固时在其基础上继续，不改回去。引擎监视文件变化，把用户的修改当作纠正处理。
- **敏感内容不落文件**：标为敏感的记忆只存数据库，文档里最多留一句不含细节的指向。
- **数据库只做索引**：向量、使用统计、强度存在数据库，可随时从文件重建。
- **技能的位置**：现有 `data/skills/` 迁入 `vault/技能/`，`skills.py` 的三处来源和加载方式不变。

## 7. 空间

长期的事不塞在对话里，而是有一个可以反复打开、持续更新的页面。目标、主题页、更新节奏合为一个东西：

| 之前分开的 | 合并后 |
|---|---|
| 目标（`goals` 表） | 一个空间 |
| 文档库的主题页 | 空间的文字内容 |
| 定时任务（`schedules` 表） | 空间的更新节奏 |

- 空间在流里以卡片出现，点开是完整页面（可含图表、数据卡片，沿用 `cards.py`）。
- 文字部分就是 `vault/主题/` 下的一页，Obsidian 里可见。
- 空间是它的产出，不是另一个聊天窗口。关于这件事的对话仍在主流里。

## 8. 外部工具

双向连接，系统是唯一事实来源，冲突时系统为准。

| 工具 | 接入方式 | 读 | 写 |
|---|---|---|---|
| 日历 | 原生端 EventKit | 是 | 是 |
| 提醒事项 | 原生端 EventKit | 是 | 是 |
| 通讯录 | 原生端 Contacts | 是 | 否 |
| Google 日历、Tasks | 引擎 OAuth，复用 `health_sync.py` 的授权流程 | 是 | 是 |
| 备忘录 | 引擎所在 Mac 的系统脚本 | 是 | 否 |

- **同步路径**：和健康数据相同，原生端读写系统数据，再与引擎交换。引擎不在线时写操作排队。
- **本地只存两样**：用于检索的缓存，和 Jurvis 自己的注解（哪次对话里建的、为什么建、事后聊了什么）。
- **删除也是记忆**：用户在别处删除或改期，注解保留为"原定……后来取消"。
- **去重**：同一条日程可能同时从系统日历和 Google 直连进来，按全局标识去重，并只从一条路写回。
- **"提醒我"分家**：纯提醒写进系统提醒事项，手机会响；需要它干活的（每周简报）留在定时任务。
- **写入权限**：新建不问；修改和删除先确认。
- **限制**：系统时钟里的闹钟第三方读不到，作息从健康数据的睡眠记录推断。备忘录只在 Mac 开着时同步，排在第一批最后。
- **沉淀**：夜间巩固从日程里提炼规律进语义记忆，不把每条日程抄成记忆。

## 9. 自我改进与学习

可改进的只有三类文件：`习惯/`、`技能/`、`例行/`。

### 9.1 闭环

```
做事 → 留经验记录 → 夜间反思 → 提出改动 → 按分级采用 → 继续观察
```

- **经验记录**：每件事一条：要求、做法、结果、信号、用到的技能。
- **信号**，按可靠程度：用户直接纠正；用户改了它的产出；用户要求重做或追问多轮；主动行为被采纳或忽略；客观结果（测试、命令是否成功）；用户在提问选项里的选择。
- **门槛**：同一模式至少出现三次才提出改动；用户明确说"以后都这样"的除外。
- **每次改动**是文档库里一个文件的变更，留有历史和依据，可撤回。

### 9.2 批准分级

| 改动 | 处理 |
|---|---|
| 对已有习惯的小修正 | 自动采用，在流里告知，可撤回 |
| 修订已有技能 | 自动采用并告知；同一技能一周内第三次修订时转为需批准 |
| 新建技能 | 需批准 |
| 新的主动例行 | 需批准 |
| 外出学来的任何东西 | 需批准 |
| 权限、安全、隐私规则 | 它不能改 |

### 9.3 学习

- **用户发起**：指定课题，它在后台学，带回一份报告和一个技能草稿。
- **任务中自发**：遇到不会的直接去查去学，接着做，并在流里说明。学到的当场可用于这次任务；沉淀为长期技能按上表批准。
- **来源**：公开网络、用户过去的文件和产出、其他助手的现成技能。
- **上限**：每个任务、每天各有时间和用量上限。
- **外部内容不可信**：学来的技能一律是草稿，不能附带新的工具权限。

### 9.4 主动行为的约束

主动行为有每日上限，被忽略几次后自动降低频率。现有主动关怀（`checkin.py`）的安静时段继续适用。

## 10. 隐私

- **敏感度标记**：每条记忆、每段经历、每条外部条目都有。来自健康、账本的数据天然敏感；日程和笔记由规则和本地模型判断；拿不准按敏感处理；用户可手动改。判断过程不经过云端模型。
- **按敏感度路由**：使用云端模型时，检索结果里的敏感条目不放进上下文，只说明有若干条未提供；请求主要涉及敏感内容时，整轮改用本地模型。
- **敏感内容不落文件、不进系统搜索。**
- **不变的规则**：经期等现有的仅本地规则保持原样（见 `HEALTH.md`）。

## 11. 找回过去的事

- **对话里问**：直接问它，走 5.3 的回忆。
- **应用内搜索**：搜索框，结果定位到流里的位置；流可按日期跳转。
- **系统搜索**：文档库页面在 Mac 上自动被收录；经历由原生端登记到系统搜索，点击跳到对应位置。网页版只有应用内搜索。

## 12. 数据模型

在现有 SQLite 上增改。现有的 `events` 表是变更通知，外部日程不使用这个名字。

| 表 | 变化 | 用途 |
|---|---|---|
| `sessions` | 加 `kind`（main、work） | 一条主流，若干后台工作上下文 |
| `messages` | 加 `episode_id`、`off_record` | 消息归属的段；无痕区间 |
| `episodes` | 新增 | 一段经历及日、周、月概要（`level`、`parent_id`） |
| `tasks` | 新增 | 跨轮任务的状态 |
| `questions` | 新增 | 待答和已答的提问、选项、建议、答案 |
| `pages` | 新增 | 文档库页面的索引：路径、类型、重要度、向量、强度、`used_at` |
| `links` | 新增 | 页面之间、页面与经历之间的链接 |
| `memories` | 保留，加 `sensitive` | 只存不落文件的敏感记忆；其余迁入文档库 |
| `goals` | 加 `page`、布局 | 空间 |
| `schedules` | 关联到空间或任务，不再关联会话 | 更新节奏、例行 |
| `external_items` | 新增 | 日历、提醒、联系人、笔记的缓存 |
| `annotations` | 新增 | Jurvis 对外部条目的注解 |
| `outbox` | 新增 | 待写回外部工具的操作 |
| `experiences` | 新增 | 经验记录 |
| `changes` | 新增 | 对习惯、技能、例行的改动：依据、分级、状态 |

## 13. 迁移

- `messages` 不动。每个旧会话变成一段或几段经历，现成的会话摘要直接作为段摘要，按时间并入主流。
- `memories` 里非敏感的条目按主题和人物归并成文档页；敏感的留在表里。
- 旧会话的 `goals`、`schedules` 改为关联到空间。
- 迁移前自动备份数据库，可回退。

## 14. 分期

| 期 | 内容 | 用户能感觉到的 |
|---|---|---|
| 1 | 主流、经历切分、跨全部历史的回忆、核心画像、旧数据迁移 | 只有一个窗口，它记得所有聊过的事 |
| 2 | 任务与提问、「等你决定」、多气泡、节奏规则 | 像人一样一步步协作 |
| 3 | 文档库、夜间巩固、日记、空间 | 能看见并纠正它的认识；长期的事有自己的页面 |
| 4 | 日历、提醒、通讯录、Google 直连、敏感度路由、备忘录 | 它知道你的日程，提醒落到手机上 |
| 5 | 经验记录、反思、分级批准、学习任务 | 越用越会做事 |
| 6 | 系统搜索、遗忘调优 | 从系统搜索找回对话 |

每期都同时改引擎、原生端和网页端。

## 15. 风险

| 风险 | 应对 |
|---|---|
| 话题串味：段切错或检索错，把无关经历混进来 | 第 1 期就建专门的测试场景；夜间合并和拆分补救 |
| 上下文每轮组装，缓存命中下降 | 稳定内容在前，段内只追加 |
| 学到错误的教训 | 次数门槛、分级批准、每次改动可撤回 |
| 外出学习被植入恶意内容 | 一律草稿、需批准、不附带权限 |
| 提问过多变成打扰 | 三条件才问；用户的选择沉淀为习惯后不再问 |
| 主动行为变成骚扰 | 每日上限，被忽略后降频 |
| 文档库被同步到云端 | 默认不同步；敏感内容不落文件 |
| 敏感判断误伤，云端模型答不了 | 说明原因，用户可改标记 |
| 文档库与数据库不一致 | 文档为准，索引可重建 |

## 16. 第 1 期：已实现的部分

和上文设计相比，实现时做了一个简化：**不新建 `episodes` 表，现有的一行 `sessions` 就是一段经历。** 这样代理核心（上下文窗口、摘要折叠、陪伴模式、代码项目、命令许可）不用改，旧数据也不需要迁移：旧会话直接就是流里较早的几段。第 12 节里 `sessions.kind`、`messages.episode_id`、`episodes` 三项因此没有做。

| 部分 | 实现 | 位置 |
|---|---|---|
| 单条流 | 消息发到 `/api/stream/messages`，由引擎决定续接哪一段或开新的一段；`/api/stream` 分页读取全部对话 | `engine/stream.py`、`engine/app.py` |
| 按停顿切分 | 安静超过 30 分钟，下一条消息开新的一段；回复写得再久也不算停顿 | `Stream.current` |
| 按话题切分 | 新消息和最近内容没有共同的词时，问一次工具模型（本机模型也问）：是接着说、回到今天早些时候的某一段、还是新话题。回到早先的就把消息移回那一段；一段里聊过三轮以上才会判成新话题 | `Memory.shifted`、`Agent.reroute` |
| 回应它主动写的内容 | 主动关怀、定时任务、后台结果写在哪一段，30 分钟内的回复就接在哪一段 | `Stream.answered` |
| 每段的记录 | 一段安静下来后，后台为它写标题和摘要（短的直接用原文），存 `digests` 表，可配向量 | `Memory.digest`、`Worker.keep_records` |
| 跨全部历史的回忆 | 每轮带上「刚才聊的」（最近一两段）和「可能相关的更早对话」（按摘要匹配，新的略优先），并从这些段里取回原话 | `Memory.background`、`Memory.excerpts` |
| 核心画像 | `data/vault/我.md`，有三条以上记忆后由后台生成，之后每天最多重写一次；每轮都在系统提示里；可以直接改这个文件 | `Memory.draw`、`Memory.portrait` |
| 找回过去的事 | `/api/stream/search` 按原话搜索；三端的侧栏或记录页可搜索并跳到那条消息 | `Stream.search` |
| 它自己翻对话记录 | 每轮带回的摘要和原话里没有时，模型可以按关键词搜索全部原话，再按消息读出前后几条的原文（有字数上限）；无痕的段搜不到，关掉记忆、代码项目里不提供 | `Stream.find`、`Stream.around`，工具 `search_conversations`、`read_conversation` |
| 无痕 | 一段可以标为不记：不读取也不写入记忆和画像，别的段也看不到它 | `sessions.incognito`，沿用 |

三端界面都改成了一个对话窗口：侧栏的列表变成「对话记录」，点一段是跳到流里的那个位置；段与段之间显示时间。

### 已知的限制

- **话题判断每条多问一次模型。** 只用本机模型时也问，每条消息多几秒；没有共同用词的消息才会问。回到早先的一段只在 36 小时内的最近四段里找。
- **相关对话的匹配**在没有配置向量模型时是按字面的：换一种说法问同一件事可能带不出来。
- **其他段的摘要会随请求发给当前使用的模型**，和已有的记忆条目一样。按敏感度区分是第 4 期的内容。
- **旧的 `/api/sessions` 接口仍然保留**，脚本和测试还在用；应用本身不再调用创建会话的接口。

## 17. 第 2 期：已实现的部分

带选项的提问、"先给东西再问"、后台任务在这之前已经有了。这一期补的是让提问和任务能跨轮、跨段保持，以及节奏规则。

和设计相比的简化：**没有单独的 `tasks` 表。** "未完的事"由三样现成的东西构成：还没回答的问题（新增的 `questions` 表）、正在跑的后台任务、长期目标。任务里"已定的决定"就是已回答的问题。

| 部分 | 实现 | 位置 |
|---|---|---|
| 问题会等你 | 回复以提问结束时，问题连同选项记入 `questions` 表，直到被回答、被新问题取代、被你关掉，或七天后过期 | `engine/asks.py` |
| 「等你决定」 | 没回答的问题常驻在输入框上方，一次显示一个；对话末尾那个问题不重复显示，它的选项就在下面 | 网页 `renderTray`，原生 `WaitingQuestions` |
| 什么算回答 | 点选项算；紧跟着的一句简短的话算；你自己又提了个问题不算，原来的问题继续等 | `Asks.heard` |
| 之后再回答 | 在「等你决定」里点选项，这条回答会回到当初提问的那一段，带着当时的上下文；隔了别的话时，会告诉模型这是在回答哪个问题 | `/api/stream/messages` 的 `answer_to` |
| 记得还有问题没答 | 别的段里还在等的问题会放进上下文，模型不会重复问，可以在合适的时候提一句 | `Asks.elsewhere` |
| 从选择里学习 | 同一类问题你两次都选了同一个答案，第三次它想问时会被拦下，改为按以往的选择做并说明 | `Asks.habit`、`Agent.ask_user` |
| 岔开再回来 | 换话题开了新的一段之后，如果下一句又说回原来的事，这句话会回到原来那一段 | `Memory.returning`、`Stream.move` |
| 节奏规则 | 提示词里写明：简单问题直接答；开放式的事一步一停；明确要办的事办完为止；三个条件都成立才问；推荐的选项放第一个；可以不继续的事给一个出口 | `engine/agent.py` 的 `ASSIST` |
| 多气泡 | 一次回复里的几段普通文字各成一个气泡；列表、表格、代码和长文保持整块 | 网页 `bubbles`，原生 `Bubbles` |

### 已知的限制

- **"一句简短的话算回答"是按长度和是否像问句判断的。** 单独一句"谢谢"不算；其他简短的话（比如"好的"）紧跟在提问后面仍会被当作回答。它不会被当成习惯，因为习惯要求答案是选项之一。
- **"同一类问题"按字面相似度判断。** 换一种问法可能认不出来，于是会再问一次；不会反过来把不同的问题当成同一类去替你做决定，因为还要求以往的答案出现在这次的选项里。
- **回到主线**：刚岔开不久的按用词判断，其余由话题判断那一次模型调用决定（见第 16 节）。
- **节奏是提示词层面的规则。** 模型是否照做取决于模型本身，测试只验证了规则确实送到了模型面前。

## 18. 第 3 期：已实现的部分

和设计相比的简化：**没有把记忆整体搬进文件再建 `pages` 索引，而是让 `memories` 表和文档库页面双向保持一致。** 检索、向量、设置页里的记忆列表都继续用表；页面是同一份内容的另一种形态，你改页面就是改表。`links` 表也没有建：链接直接写在页面里，由 Obsidian 解析。

| 部分 | 实现 | 位置 |
|---|---|---|
| 文档库 | `data/vault/`：`我.md`、`人物/`、`主题/`、`习惯/`、`技能/`（指向 `data/skills` 的链接）、`日记/` | `engine/vault.py` |
| 记忆归页 | 每条记忆属于一页；从对话里抽取时由模型选页（优先用已有的页），其余按第一个标签归页，都没有就进 `主题/杂记` | `Memory.extract`、`Vault.sync` |
| 页面格式 | 开头是类型和更新日期，正文每行一条事实，结尾是来源日期（链接到日记）；提到人物页的名字时自动加链接 | `Vault.render` |
| 你改页面 | 加一行是新增一条记忆，删一行是停用那条记忆，改一行是停用旧的、新增新的；新建一页、删掉一页同理 | `Vault.take` |
| 停用而不是删除 | 你从页面里拿掉的记忆只是停用，在记忆页里还能重新启用；之后只是在对话里又被听到，不会自己回来 | `Memory.save` |
| 同步时机 | 引擎每 15 秒核对一次两边；每次整理记忆之后也会核对 | `Worker.keep_records` |
| 日记 | 每天一页，按时间列出当天每一段对话的标题和记录，并链接到涉及的页面；由 Jurvis 生成，不读回 | `Vault.diary` |
| 夜间巩固 | 每晚 3 点之后第一次空闲时运行一次：先读入你的修改，给当天的对话写记录，整理有新内容的页面，重写核心画像 | `Memory.consolidate` |
| 整理页面 | 合并重复的事实；新事实取代旧事实时保留新的并注明"之前是……"；你写的行和目标自己的那一行不交给模型改写，只作为参照；模型的改写如果让页面变长，就不采用 | `Memory.tidy` |
| 空间 | 建立长期目标时自动获得 `主题/` 下的一页；目标页列出这一页的事实、同一段对话里设的定时任务、以及聊到过它的对话 | `Memory.space`、`/api/spaces/{id}` |
| 界面 | 目标页的每个目标可以"打开"成空间；记忆页说明文档库的位置，Mac 上可以直接打开文件夹 | 网页 `goals.js`，原生 `SpaceView` |

### 已知的限制

- **每行一条事实。** 页面里的多行段落会被拆成多条；标题行不算事实。
- **改一行等于换一条。** 被改动的那条记忆会失去原来的重要度和出处，按你写的新行重新计。
- **敏感内容现在也会写进文件。** 敏感度标记是第 4 期的内容；在那之前，文档库里有全部启用的记忆。文档库在 `data/` 下，仅本人可读，默认不同步。
- **日、周、月的层级摘要没有做。** 日记是按天汇集每段的记录，没有再往上合成周和月。
- **空间只有文字。** 没有图表和数据卡片；定时任务靠"在同一段对话里设立"来和目标关联。
- **`技能/` 是一个指向 `data/skills` 的链接**，技能文件没有搬动。

## 19. 用真实模型跑过之后

2026-11-22，在一份独立的数据目录上用本机模型（Qwen 27B，和实际配置相同）跑了多轮完整对话和一次夜间巩固，另外在真实数据的副本上跑了首次同步。iPhone 界面在模拟器里看过，Mac 界面用离屏截图看过。

### 跑出来并已修的问题

| 现象 | 原因 | 改动 |
|---|---|---|
| 只用本机模型时从不按话题分段，换了话题的内容全堆在一段里 | 话题判断只允许云端模型 | 本机模型也问；并且能把消息送回早先的一段（`Memory.shifted`） |
| 中文里几乎从不触发话题判断 | 相似度把单个汉字也算作共同用词，任何两句话都"相似" | 只按词和双字比较 |
| 聊别的之后问回先前的事，细节答错 | 新的一段里只有那段的摘要 | 消息回到原来那一段，带着完整的上下文 |
| 同一件事出现两个页面（先记了事实，后建了目标） | 目标建页时不知道同一段里已有的页面 | 只属于这一段的页面并入目标页；抽取时告诉模型这段对话的目标页 |
| 目标更新后，页面和画像里还是旧内容 | 目标的那一行只在建立时写一次 | 每次更新目标都重写那一行 |
| 夜间整理对有目标行的页面不生效 | 要求模型把你写的行逐字抄回，抄错一个字就整页作废 | 你写的行不再交给模型，只作参照 |
| 核心画像是英文标题，写了"未知"的栏目和猜测 | 提示词没有约束 | 用事实的语言写，没有内容的栏目不写，只写关于人的事实，新事实优先 |
| 一段对话的记录只有一行标题 | 模型偶尔只输出标题 | 这种情况下把这段的开头和结尾补在标题下面 |
| 连续三次只提问、不给任何内容 | 节奏只靠提示词 | 上一条回复只有问题、这一条又什么都没给就提问时，提问工具拒绝一次并要求先把事做了（`Agent.only_asked`） |
| "谢谢"被当成对等待中问题的回答 | 按长度判断 | 单独的道谢不算回答 |
| 在历史记录里点一段旧对话，页面不跳过去（Mac 和 iPhone） | 跳转完成后清除目标又触发了一次"滚到底部" | 清除目标不再触发滚动 |
| 空间里的对话摘要露出 `User:` | 短对话的记录是原文 | 显示为"我："和"Jurvis：" |

### 看到但没有改的

- **回复偏长。** 要一份计划时，模型问一个问题后把整份八周计划写在一条消息里。这符合现在的规则（"用户要你做的事，问清必须知道的，然后做完"），但和 Muse 那种短消息的观感有距离。
- **抽取会记下没有价值的事。** 本机模型会把"用户请求助手制定跑步计划"这类请求当成事实记下来。提示词已加了一条说明，没有再用真实模型验证效果。
- **开放话题不一定给按钮。** 问"要不要学一门乐器"时，模型给了概览并在文字里问偏好，没有用选项按钮。
- **等待中的问题在手机上横向排列**，第三个选项要横滑才看得到，没有提示。
- **键盘弹出时**，等待中的问题、输入框和键盘一起占掉大半屏。
- **本机模型每条回复 35 到 110 秒**，话题判断另加几秒。


## 20. 上下文保持得短（2026-11-24）

起因是 arXiv 2611.05306《You don't need long context》：把上下文压短并频繁压缩，长任务的准确率基本不掉。它不涉及记忆条目本身，和这里"短窗口、折叠摘要、原文永久保留"的做法一致；对照之后补了下面几处。

| 部分 | 实现 | 位置 |
|---|---|---|
| 它自己翻对话记录 | 见第 16 节的表 | `Stream.find`、`Stream.around` |
| 在线模型带多少历史 | 原来固定是本机的 4 倍，现在是设置项（1 到 4 倍，默认 4）；一轮之内的工作上下文仍是 4 倍，不随它变 | `context.cloud_history`、`CLOUD_GOAL_SCALE` |
| 长任务的状态简报 | 一轮里工具往返太多、截短旧结果之后仍放不下时，由模型把前面的经过写成简报（正在做什么、确定的事实、已做的、走不通的、剩下的），替换掉经过本身，最近两轮工具往返保留原样。本机和在线模型都这样 | `Agent.handoff` |
| 摘要里带出处 | 折叠摘要时要求写明产物的文件名或日期，折叠的内容带上日期范围，之后能按它翻回原文 | `SUMMARIZE`、`Memory.fold` |
| 每步压缩（默认关） | 目标和后台任务里，每做完一步就写一次简报，下一步只带任务和简报 | `context.step_compaction` |
| 摘要写成简报（默认关） | 折叠时不写完整摘要，只留还没办完的事、你定下的做法、已定的数字，以及去哪找原文 | `context.brief_summary`、`HANDOFF` |

后两项只有默认对话模型是在线模型时才能打开，换回本机模型后自动不生效：它们每一步或每次折叠多一次模型调用，本机模型一次回复要半分钟以上。开关在网页版的记忆设置里；原生端没有这一页设置，暂时只能在网页版改。

### 已知的限制

- **这几项都没有用真实模型跑过。** 测试只验证了简报在该出现的时候出现、内容送到了模型面前。
- **4 倍还是 2 倍没有结论。** 需要拿网关的实际账单比较后再改默认值。
- **每步压缩在论文自己的结果里比"放不下才压缩"低 1 到 6 分**，换来的是更短的上下文。简报没写进去的细节，下一步就看不到了；同一个调用可以重新发一次。
- **摘要写成简报之后，已经聊完的话题只剩一行指向**，问回去时靠翻对话记录取原文。
