# 部署网页版（PWA）

网页版随引擎一起提供，源码在 `web/`，是不需要构建的原生 ES 模块。引擎跑起来它就在了，没有单独的部署步骤：

```
https://<Mac 的地址>:18777/app/
```

它适合 Android 手机、Windows / Linux 电脑，以及不想装 App 的 iPhone 和 iPad。

## 打开和配对

1. 在设备上打开 `https://<Mac 的局域网或 Tailscale 地址>:18777/app/`（在 Mac 自己的浏览器里是 `https://127.0.0.1:18777/app/`）。浏览器会提示证书不受信任，因为引擎用的是自签名证书，选择继续访问。
2. 在 Mac 的 Jurvis App 里 **设置 → 配对 iPhone 或 iPad** 创建邀请，把链接或配对码粘贴到网页上。邀请 5 分钟内有效，只能用一次。

每个浏览器都要配对一次，包括 Mac 自己的浏览器。

配对后凭据保存在这个浏览器里。在 Mac 的设置里可以随时撤销某台设备。

## 装到主屏幕

「添加到主屏幕」之后要像 App 一样全屏打开、离线也能显示外壳，浏览器要求页面来自**受信任的 HTTPS**。自签名证书下浏览器不允许注册 Service Worker，所以需要给引擎前面加一个受信任的证书。三种做法，选一种：

### Tailscale Serve（推荐）

Mac 和设备都已经登录同一个 Tailscale 账号时，让 Tailscale 用它签发的证书把引擎转出去：

```bash
tailscale serve --bg https+insecure://127.0.0.1:18777
```

然后在设备上打开 `https://<Mac 的机器名>.<你的 tailnet>.ts.net/app/`。只有你的 tailnet 里的设备能访问。需要先在 Tailscale 管理后台开启 HTTPS 证书。

### mkcert

在局域网里使用时，用 [mkcert](https://github.com/FiloSottile/mkcert) 建一个本地根证书，把根证书装到每台设备上并设为信任，再用它签发的证书配一个反向代理（如 Caddy）转发到 `https://127.0.0.1:18777`。

### 自己的域名和反向代理

有域名时，用 Caddy 或 nginx 配上正式证书，反向代理到引擎。上游是自签名的 HTTPS，代理需要关闭对上游证书的校验；对话是流式返回的，要关掉响应缓冲。**不要让这个地址对公网开放**，至少限制到 VPN 或内网。

这三种做法是按各工具的常规用法写的，本项目目前只验证过自签名证书下的直接访问。

装好受信任的证书后：

- **iPhone / iPad**：Safari 打开 → 分享 → 添加到主屏幕。
- **Android**：Chrome 打开 → 菜单 → 安装应用（或「添加到主屏幕」）。
- **桌面 Chrome / Edge**：地址栏右侧的安装图标。

## 修改网页版

直接改 `web/` 里的文件，刷新页面即可。引擎对 `/app` 下的文件返回 `Cache-Control: no-cache`，不会读到旧版本。改了外壳文件后把 `web/sw.js` 里的缓存名加一，已安装的 PWA 才会更新离线外壳。

界面约定：只用黑、白、绿三种颜色；图标用 `web/icons.js` 里内嵌的 Lucide 图标（用 `scripts/web_icons.py` 增加）；下拉、开关、对话框等控件用 `web/ui.js` 里的组件，不用浏览器默认样式。

## 和原生 App 的差别

网页版覆盖对话、工作台、素材、短剧、家居、记忆和设置。只能在 Mac 上做的事情不在网页版里：连接本机的代码项目文件夹、添加需要在 Mac 上运行命令的 MCP 服务。
