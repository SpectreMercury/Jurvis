# 不在屏幕前也能办事

这一页讲让 Jurvis 在你没有看着它的时候也能工作的几样东西：它怎么找到你、什么不用再问你、它能看到你一天里的什么、事情发生时它怎么自己动起来，以及数据怎么保住。

每一项的开关都在 **设置** 里。网页版有全部设置；原生 App 里有通知、日历与通讯录、不用再问的操作，其余（Apple 推送密钥、邮箱的发信开关、备份、电源）在网页版设置里改。

## 通知

Jurvis 有三类事会主动告诉你：

| 是什么 | 例子 |
|---|---|
| 主动问候 | 身体数据变差时的那一句（见[健康](HEALTH.md)） |
| 后台结果 | 后台任务、定时任务、事件触发做完了；一条回复因为太久转到了后台 |
| 等你确认 | 它想运行命令、点网页、控制设备、打电话、发邮件，在等你点允许 |

App 或网页开着时，它们自己弹通知。**关着时靠推送**，引擎只推给没开着的设备（最近 15 秒内向引擎要过东西的设备算开着）。

| 设备 | 怎么开 | 需要什么 |
|---|---|---|
| 浏览器、装到主屏幕的网页版 | 网页版 设置 → 通知 → 「这台设备的浏览器接收推送」 | 浏览器信任这个地址的证书：用 Tailscale Funnel / Serve 的地址或 `localhost`。自签名证书的局域网地址注册不了 Service Worker，开不了推送（见[网页版](PWA.md)）。iPhone 和 iPad 要先「添加到主屏幕」。 |
| iPhone / iPad App | App 的 设置 → 通知 → 「打开」，并在网页版 设置 → 通知 里填 Apple 推送密钥 | 你自己 Apple 开发者账号里的一把 APNs 密钥（.p8）、Key ID 和 Team ID。Jurvis 没有自己的服务器，没法替你发。 |

**取得 Apple 推送密钥**：developer.apple.com → Certificates, IDs & Profiles → Keys → 新建，勾选 Apple Push Notifications service (APNs)，下载 `.p8`（只能下载一次），把文件内容、页面上的 Key ID 和账号的 Team ID 填进设置。App 需要用同一个团队签名，并且 App ID 打开了 Push Notifications。从 Xcode 直接运行的版本用 Apple 的开发环境，TestFlight 和正式版用生产环境，App 登记时会告诉引擎用哪一个。

「等你确认」的通知在 iPhone 上带 **允许 / 拒绝** 两个按钮，不用打开 App 就能回答；「允许」需要先解锁。

**隐私**：推送的正文是消息的前 180 个字。发给浏览器的内容按 Web Push 标准端到端加密，推送服务看不到；发给 iPhone 的内容经过 Apple 的推送服务，Apple 能看到。密钥保存在 `data/security/push.json`，只有当前用户可读。无痕对话里的事不发通知。

## 不用再问的操作

确认卡片有四个回答：

| 回答 | 效果 |
|---|---|
| 允许 | 只这一次 |
| 本任务内都允许 | 这段对话里同一种工具不再问，引擎重启后失效 |
| 以后都允许 | 这**一类**操作以后都不问，直到你在 设置 → 不用再问的操作 里收回 |
| 拒绝 | 不做，并把控制交还给你 |

「一类」划得很窄，卡片上会写清楚这次点了会放行什么：

| 工具 | 一类是 | 例子 |
|---|---|---|
| 命令 | 一个程序加它的子命令 | `git status …`、`npm test …`、`ls …` |
| 浏览器点击和输入 | 一个网站 | `www.tablecheck.com` |
| 智能家居 | 一台设备的一个动作 | 「客厅灯」`turn_on` |
| MCP 工具 | 一个服务的一个工具 | `github · create_issue` |

**永远每次都问**，没有「以后都允许」：电话、邮件、门锁、门、摄像头、在网页里运行脚本、看上去有风险的命令（`rm -r`、`sudo`、`git push` 等），以及用 `;`、`|`、`&&`、重定向串起来的命令和 `python`、`sh`、`curl` 这类给什么就运行什么的程序。

## 日历、提醒事项和通讯录

引擎自己读不到这些。**iPhone、iPad 或 Mac 上的 Jurvis App** 在你允许之后读取，把一份副本送到你的 Mac：

| 内容 | 范围 |
|---|---|
| 日历 | 过去一周到未来两个月的日程：标题、时间、地点、所属日历、备注的前 500 字 |
| 提醒事项 | 还没完成的提醒：标题、到期时间、所属列表 |
| 通讯录 | 姓名、公司、电话、邮箱（最多 5000 人） |

在 App 的 **设置 → 日历与通讯录** 里逐项打开，系统会分别询问权限。之后每次打开 App 更新一次（间隔不短于 15 分钟），每次都是整份替换。关掉某一项会同时清掉 Mac 上那一份副本。

- **谁能读**：默认只有本机模型。要让云端模型也能读，在网页版 设置 → 日历与通讯录 里逐项改成「本机和云端模型」。
- **通讯录从不整本给模型**：它只能按名字（或公司、邮箱、号码的一段）查一个人，最多返回 6 个匹配。
- **上下文里带着今天**：能读日历的模型，每次回复都会看到从现在起 24 小时内的日程（最多 6 条），所以订位、约时间之前它会先看有没有冲突。
- **只新增，不改不删**：它用「加日程」「加提醒」做出来的条目先排队，由第一台打开着 App 的设备写进系统日历或提醒事项，再由你的 iCloud 等账户同步到别的设备。只用网页版时没有设备能写入，它会如实告诉你。
- 副本只在 App 打开时更新：超过 36 小时没更新，它读的时候会被提醒这份数据是哪天的。

## 事件触发

定时任务按时间跑，事件触发按**发生了什么**跑。在对话里直接说：

| 你说 | 它等的是 |
|---|---|
| 「房东来邮件的时候告诉我他要什么」 | 收到某个发件人、或提到某些词的邮件 |
| 「开会前半小时把相关邮件整理给我」 | 日历上的日程开始前若干分钟 |
| 「餐饮预算用到八成时提醒我」 | 本月某一类（或全部）支出达到预算的百分之多少 |
| 「大门打开时告诉我」 | 一台智能家居设备的某个状态变成某个值 |

事情发生时，这件事作为后台任务在当初设置它的那段对话里运行，结果发在那里，并按上面的规则通知你。**目标** 页的「事件触发」列出全部，可以取消；最多 20 个。

- 检查不用模型：邮件每 5 分钟、日程每分钟、预算每 10 分钟、设备每 2 分钟看一次。
- 第一次检查只记下现状，不会为已经在收件箱里的邮件或本来就开着的门触发。
- 同一批到的几封邮件是一次运行；上一次还没跑完时不叠加；预算每月只提醒一次；日程每个只提醒一次。
- 邮件按那段对话所用模型的权限读取：只给本机模型的邮箱，不会喂给由云端模型执行的任务。
- 引擎没在运行（Mac 睡着了）时什么都不会触发，见下面的「电源」。

## 发邮件

邮件默认只读。在网页版 **设置 → 邮件** 里给某个邮箱点「不发信」把它切成「可以发信」之后，Jurvis 才能从这个邮箱发信或回复来信：

- Gmail 和 Outlook 需要多一项授权（`gmail.send`、`Mail.Send`），会让你重新登录一次；在 Google / Microsoft 的开发者应用里也要把这项权限加上。iCloud、QQ、163、126 和其他 IMAP 邮箱用同一个专用密码走 SMTP。
- **每一封都先给你看全文**（发件邮箱、收件人、主题、正文），你点了允许才发。邮件没有「本任务内都允许」和「以后都允许」。
- 收件人只能是完整的邮箱地址，一封最多 10 个；回复时默认回给来信人，并接在同一个会话里。
- 引擎不保存发出的邮件。Gmail 和 Outlook 会把它存进「已发送」；走 SMTP 的邮箱是否保存，取决于服务商和你在它那里的设置。

还没有做的：LINE、WhatsApp、iMessage 等即时消息。它们面向个人账号没有可用的发送接口，企业接口又不能随意给陌生商家发消息。

## 私密的记忆只给本机模型

用云端模型时，取回的记忆和别的对话的摘要会随请求发给它。现在其中私密的那部分不再发：

- **私密的记忆**：关于健康和身体、心理状态、收入负债、证件、住址、性取向、官司、家庭和感情矛盾的事实。提取记忆时由模型标记，另有一组关键词兜底；在 **记忆** 页编辑一条记忆可以手动改这个标记。
- **陪伴对话**，以及产生过私密记忆的那些对话：它们的摘要和原话不会作为「之前聊过的」带给云端模型，云端模型翻对话记录时也翻不到。
- **画像**（`data/vault/我.md`）：有私密记忆时，云端模型拿到的是只用公开事实另写的一份（`data/portrait-cloud.md`）；那一份还没写出来之前，它什么画像都拿不到。

想让云端模型也看到全部，在 设置 → 记忆 里关掉「私密的记忆只给本机模型」。

**没有覆盖的**：你正在进行的这段对话本身。在一段用云端模型的对话里说出的话，包括陪伴对话，照样会发给那个模型。文档库的文件里仍然有全部记忆，它们只在这台 Mac 上。

## 评价一条回复

每条回复下面有 👍 和 👎。点 👎 可以写一句哪里不对：它会进入 Jurvis 的工作日志和「改进清单」（**日志** 页），和它自己记下的失误放在一起，你问它「最近哪里做得不好」时它会引用。对一条主动问候点 👎，它问候的那几件事一周内不会再提。

主动问候另外有一条规则：你没有回的问候会让下一次等得更久，连续每忽略一次间隔变为四倍（1 小时、4 小时、16 小时），最长一天；你回了任何一条就恢复。

## 备份

引擎每晚（凌晨 3 点之后第一次空下来时）自动备份一次，不需要停引擎：

- **内容**：数据库（对话、记忆、账本、健康、定时任务等，用 SQLite 自带的在线备份）、`data/` 下的设置文件、`security/`（密钥和令牌）、`vault/`、`workspace/`、`skills/`。生成的图片和视频很大，默认不带，可以在设置里打开。
- **位置**：默认 `data/backups/jurvis-<日期-时间>/`，保留最近 7 份。它和数据在同一块盘上，防得住误操作和数据库损坏，防不住硬盘坏掉；在 Mac 上的网页版 设置 → 备份与电源 里可以改到另一块硬盘。
- **注意**：备份里有和 `data/security/` 一样的密钥。放进 iCloud Drive、Dropbox 这类会同步的文件夹，就等于把密钥交给了那个服务。

**恢复**：停掉引擎，把某一份备份里的文件复制回 `data/`（`jurvis.sqlite3` 覆盖原文件，并删掉旁边的 `jurvis.sqlite3-wal` 和 `-shm`），再启动引擎。恢复没有做成按钮，也没有自动化测试过整个流程。

## 开机自启和电源

```bash
./scripts/install-service.sh          # 登录后自动启动，停了 15 秒内重新拉起
./scripts/install-service.sh status
./scripts/install-service.sh remove
```

它安装一个 launchd 用户服务（`~/Library/LaunchAgents/app.jurvis.engine.plist`）。安装前要先停掉手动启动的引擎。更新代码后用 `launchctl kickstart -k gui/$(id -u)/app.jurvis.engine` 重启。

Mac 睡着之后，定时任务、事件触发、主动问候、电话回调和推送都会停，醒来后错过的定时任务补跑一次。设置 → 备份与电源 里的「接着电源时不让 Mac 自己睡着」打开后，引擎会在接着电源时阻止系统空闲休眠（屏幕可以关）；合上盖子、用电池时仍然会睡。要一直在线，需要一台常开的 Mac。

## 已知的限制

- **iPhone 推送和日历同步没有在真机上验证过。** 引擎一侧有自动化测试（加密、APNs 请求的形状、哪些设备该推），原生代码在 Mac 和 iOS 模拟器上编译通过，但没有用真实的 Apple 推送密钥发过一条推送，也没有在设备上走过日历、提醒事项、通讯录的授权和同步。
- **浏览器推送没有对着真实的推送服务发过。** 加密用标准里的解密步骤验证过，订阅和发送只对着模拟的服务测过。
- **事件触发、发邮件、日历这些工具没有用真实模型跑过**：模型是否在合适的时候想到用它们、参数给得对不对，测试里是脚本扮演的。
- **launchd 服务**的文件格式校验过，没有在这台机器上安装和长期运行过。
- 备份、电源和邮箱发信开关只在网页版设置里。
