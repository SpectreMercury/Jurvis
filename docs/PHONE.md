# 打电话

Jurvis 可以替你给餐厅等商家打电话：订位、问营业时间、改期或取消预订。你在对话里说「帮我给小南国打电话订周六晚上 7 点 4 位」，它确认好号码和细节后请你批准，然后拨出去、跟对方说话，挂断后把结果和通话内容告诉你。

电话走的是**你自己的电话服务商账户**。Jurvis 没有自己的账户：对方看到的是你的号码，话费记在你的账上。

## 需要什么

| | |
| --- | --- |
| 电话服务商 | Twilio 或 Telnyx 的账户，里面有一个能打出电话的号码 |
| 公网地址 | 服务商要从公网连到这台 Mac 传通话声音。用 Tailscale Funnel，或在 `.env` 里设 `JURVIS_PUBLIC_URL`，见[部署](DEPLOY.md) |
| 语音模型 | 本机的语音识别和语音合成（「设置 → 语音」里显示已安装） |

## 绑定

在「设置 → 电话」里选服务商，按页面上的说明填：

- **Twilio**：Account SID 和 Auth Token。主叫号码留空时用账户里的第一个号码。要打往的国家需要先在 Twilio 后台的 Geo permissions 里勾选。
- **Telnyx**：API Key。号码要分配给一个 Voice API Application（Webhook API Version 选 API v2），并配好 Outbound Voice Profile。Application ID 留空时用主叫号码所分配的那个。填上 Public Key 后，Jurvis 会核对每条通话状态确实来自 Telnyx。

保存前 Jurvis 会向服务商核对一次凭据。凭据存在 `data/security/phone.json`，只有你的用户能读，接口不会把它们返回给任何设备。

「默认国家区号」用于没写区号的号码，例如填 `+86` 后，`021-6123 4567` 会按 `+862161234567` 拨打。

## 一通电话是怎么打的

1. 助理调用 `phone_call`，对话里出现确认卡片：打给谁、哪个号码、以谁的名义、要办什么。**每一通都要你批准**，「总是允许」对电话不生效。
2. 引擎让服务商拨号。对方接起后，服务商打开一条到 `/phone/stream/<令牌>` 的 WebSocket，双向传 8 kHz 的电话声音。
3. 听到的声音在本机识别成文字，交给模型决定说什么，再在本机合成语音播给对方。对方插话时，正在播的话会停下。
4. 挂断后，通话内容和结果记在「设置 → 电话 → 最近的通话」里，也回到对话中。通话进行时可以在那里点「挂断」。

## 订好后自动加进日历

电话里对方确认了具体的日期和时间，结果又是「办妥了」，这次预订就会自动加进你的日历：

- 标题是「店名 · 几位」，地点是店名，备注里有通话结果、对方叮嘱的事（例如座位保留多久）和店里的电话，提前 2 小时提醒，时长按 2 小时算。
- 时间按**店所在地的时区**记。给东京的店订 19:00，你人在新加坡时日历上显示 18:00，到了东京显示 19:00。新加坡、日本等只有一个时区的国家按电话区号判断；美国这类多时区国家按你设备自己的时区记。
- 由 Mac、iPhone 或 iPad 上的 Jurvis App 写入系统日历，第一次会请你允许「添加日程」。Jurvis 只添加，不读取你的日历。
- 一条日程只由一台设备添加一次，加到「新日程默认加入」的那个日历里，再靠你的日历账户（iCloud、Google 等）同步到其他设备。所以手机和电脑要用同一个日历账户，才会两边都出现。
- 添加的那台设备上 App 要开着；都没开的话，下次打开时补上。网页版不能写日历，只能在通话记录里看到这条日程的状态。
- 只是「没有完全办妥」、或者对方没确认具体时间的，不会加进日历。

## 固定的规矩

这些写在代码里（`engine/call.py`、`engine/phone.py`），不靠提示词：

- 开口第一句一定说明这是替某人打电话的 AI 助理；被问到是不是真人时如实回答。
- 一通电话最长 5 分钟、最多 24 轮；对方一直不出声，问一次「还在吗」后挂断。
- 同一时间只打一通。
- 不拨紧急号码和短号码，不拨按分钟收费的声讯号码。
- 通话中模型只能说话、按键、挂断，用不了别的工具。
- 提示词要求它只说这通电话需要的信息，不答应订金、预付、最低消费等任何要花钱的事；遇到这些就说「我跟本人确认后再回电」。

## 隐私

- 通话声音经过电话服务商；识别和合成都在这台 Mac 上。
- 对方说的话（文字）和你的要求会交给当前的聊天模型：用本机模型时不出这台 Mac，用云端模型时会发给它。
- `/phone/` 下的两个地址是公网上唯一不需要配对凭据的入口。每个地址里带一个只对这一通电话有效的随机令牌；通话状态还会核对服务商的签名（Twilio 始终核对，Telnyx 在填了 Public Key 时核对）。

## 已知的限制

- 还没有用真实的服务商账户打过真实的电话。验证到的是：按两家官方文档实现并有单元测试；用本机真实的语音模型跑过电话音质下的模拟对话。
- 每轮回应大约慢 2 到 3 秒（等对方说完 0.8 秒，加识别、模型、合成）。对方句中停顿较长时，助理会等对方接着说完再一起回答。
- 语音识别在数字和人名上会出错（例如把「七点四位」听成「7.4 位」），所以助理会在挂断前复述一遍关键信息。
- Twilio 没有通话中按键的接口，语音菜单的按键是把按键音混进声音里发出去的，个别线路上可能不被识别；Telnyx 走的是它的按键接口。
- 写入系统日历的部分只确认了能编译，还没有在真机或模拟器上实际加过一条日程。
- 只支持打出，不接听来电。号码能打往哪些国家、对方看到什么号码，由你的服务商账户决定。

## 新加坡和日本

- 在服务商后台把新加坡（+65）和日本（+81）加进允许拨打的国家，否则拨号会被服务商拒绝。
- 主叫号码用外国号码时，店里看到的是国际来电，可能不接。常打哪个国家，建议在服务商那里买一个当地号码作主叫；日本号码通常需要先提交身份或地址资料审核，以服务商后台的要求为准。
- 日本的免费电话（0120、0800 开头）一般不能从国外线路拨通，请用店里的普通号码。
- 通话语言由助理按店所在地选：日本用日语，新加坡用英语，你也可以在对话里指定（例如「用中文打」）。结果总是用你自己的语言汇报。
- 「默认国家区号」只能填一个。另一个国家的号码请带上区号（+65 / +81），助理查到的号码通常已经带了。
